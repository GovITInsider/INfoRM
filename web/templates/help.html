What is INfoRM?

INfoRM (ICMP Network Reachability Monitor) is a lightweight network monitoring tool designed to track the reachability and status of network devices using ICMP pings. It provides both a high-level overview (NOC View) and a detailed device management interface, along with alarm history and a web-based management GUI.

It is designed to be simple to run, easy to understand at a glance, and useful for both day-to-day operations and wall-mounted monitoring displays.

Understanding Device Statuses

Every monitored device can be in one of the following states:

  • Up — The device is responding to pings normally.
  • Pre-Alarm — The device has missed some pings but has not yet reached the alarm threshold.
  • Down — The device has failed enough consecutive pings to trigger an alarm.
  • Unknown — The device has not been checked yet (usually right after being added or after a database reset).

How Monitoring Works

INfoRM periodically sends ICMP pings to all monitored devices. The behavior is controlled by two main concepts:

Failures

The Failures column on the Devices page shows how many consecutive ping attempts have failed for that device. Every time a ping succeeds, the failure count resets to 0. Every time a ping fails, the count increases by 1.

Pre-Alarm and Down Threshold

INfoRM uses a countbeforealarm setting (default is usually 3). This means:

  • If a device fails 1 or 2 pings in a row → Status becomes Pre-Alarm
  • If a device fails 3 or more consecutive pings → Status becomes Down and an alarm is logged

This gives you a warning period (Pre-Alarm) before treating a device as fully down.

The Devices Page

This page shows a detailed, filterable, and searchable list of all devices.

Column Explanations
  • Asset Tag — Optional unique identifier for the device.
  • IP Address — The IP address being monitored.
  • Name — Friendly name of the device (optional).
  • Building — Building or site where the device is located.
  • Location — More specific location (e.g. "MDF", "Closet 3").
  • Comments — Comments/Description.
  • Status — Current reachability status (Up, Pre-Alarm, Down, or Unknown).
  • Monitored — Whether the device is actively being pinged.
  • Failures — Number of consecutive failed pings.
  • Last Checked — Timestamp of the last ping attempt.

The NOC View

The NOC View provides a high-level, color-coded overview of all buildings and their device status. It is designed to be viewed on wall monitors or used for quick situational awareness.

Status and Response Time Cards

At the top of the NOC page you will find summary cards showing the total number of devices in each state (Up, Pre-Alarm, Down, Total) as well as minimum, average, and maximum response times.

Building Status
  • Red — All monitored devices in the building are down.
  • Yellow — Some devices in the building are down or in pre-alarm.
  • Green — All monitored devices in the building are up.

Buildings with issues are shown as cards at the top, followed by healthy buildings in a compact list.

Alarm History

This page shows a log of alarm and clear events. An alarm is recorded when a device transitions to Down. A clear event is recorded when a previously down device returns to Up.

Auto-Refresh Behavior

  • NOC View: Automatically refreshes (configurable in config/config.yaml).
  • Devices Page: Auto-refresh is on by default but can be disabled manually.
  • Landing Page: Does not auto-refresh.

Management GUI

INfoRM includes a protected web-based management interface, making it easy to manage buildings and devices without using the command line.

Accessing the Management Area
  • Click Admin in the top navigation bar, or go directly to /manage.
  • You will be redirected to the login page.
  • Log in using your admin credentials.
What You Can Do
  • Buildings — Add, edit, and delete buildings. This helps maintain consistency across the system.
  • Devices — Add, edit, and delete devices. When adding or editing a device, you must select a building from the dropdown list (only existing buildings are allowed).
Notes
  • The Management GUI requires login and is only available to authorized administrators.
  • Changes made in the Management GUI are picked up automatically by the monitoring system.
  • The CLI is still available for scripting or advanced use cases, but the web interface is recommended for most day-to-day management.

Using the CLI

While the web-based Management GUI is now the recommended way to manage buildings and devices, the command-line interface remains available for scripting, automation, or advanced users.

Common Commands
  • create-admin — Create the initial admin user for the web interface.
  • add-device — Add a new device via the command line.
  • list-devices — View all devices.
  • edit-device <ip> — Edit an existing device.
  • search-devices <term> — Search across multiple fields.
